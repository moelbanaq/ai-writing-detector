# Benchmark Suite & Empirical Validation

## 1. Dataset Taxonomy & Categories

The benchmark suite (`data/benchmark/dataset.json`) evaluates system performance across diverse genres and generator models:

| Category | Description | Primary Characteristic |
| :--- | :--- | :--- |
| `human_academic` | Peer-reviewed experimental papers (crystallography, biochemistry, neuroscience). | High lexical density, passive voice, domain abbreviations. |
| `human_technical` | Systems engineering, distributed systems, kernel documentation. | Dense technical nomenclature, code fragments, exact bounds. |
| `human_casual` | First-person narratives, essays, colloquial memoirs. | High syntactic variance, colloquial idiom, emotional punctuation. |
| `ai_gpt4o` | Text generated by OpenAI GPT-4o. | Symmetrical clauses, frequent rhetorical signposts ('vital role', 'delve'). |
| `ai_claude35` | Text generated by Anthropic Claude 3.5 Sonnet. | Balanced transitions, analytical synthesis tone, nuanced vocabulary. |
| `ai_gemini` | Text generated by Google Gemini 1.5 Pro. | Exploratory framing, structured headings, comprehensive summaries. |
| `ai_edited` | AI drafts edited or polished by human writers. | Partial marker removal, modified sentence lengths. |
| `human_edited` | Human writing lightly polished with grammar/style LLM tools. | Preserved human reasoning structure with standardized diction. |
| `adversarial` | Deliberate adversarial attacks (prompt injection, rare synonym attacks). | Prompts demanding human label, hyper-rare terminology. |

## 2. Dataset Splitting & Stratification Protocol

To prevent data contamination and ensure rigorous scientific validation, all evaluation splits follow a **stratified 60% / 20% / 20% protocol**:
- **Train Split (60%)**: Used solely for fitting logistic calibration weights.
- **Validation Split (20%)**: Used for hyperparameter tuning, threshold selection, and ECE evaluation.
- **Test Split (20%)**: Frozen, untouched test data evaluated once to report final publication metrics.

---

## 3. Evaluation Metrics

The benchmark suite calculates the full battery of standard statistical performance metrics:

1. **Accuracy**: $\frac{\text{TP} + \text{TN}}{\text{Total}}$
2. **Precision**: $\frac{\text{TP}}{\text{TP} + \text{FP}}$
3. **Recall (Sensitivity)**: $\frac{\text{TP}}{\text{TP} + \text{FN}}$
4. **Specificity**: $\frac{\text{TN}}{\text{TN} + \text{FP}}$
5. **False Positive Rate (FPR)**: $1 - \text{Specificity}$
6. **False Negative Rate (FNR)**: $1 - \text{Recall}$
7. **$F_1$ Score**: $\frac{2 \cdot \text{Precision} \cdot \text{Recall}}{\text{Precision} + \text{Recall}}$
8. **ROC-AUC**: Area under the Receiver Operating Characteristic curve.
9. **Brier Score**: Quadratic accuracy of probability forecasting.
10. **Expected Calibration Error (ECE)**: Bin-weighted absolute deviation between predicted confidence and true accuracy.

## 4. Benchmark Commands

```bash
# Validate dataset format and integrity
npm run dataset:validate

# Run comprehensive benchmark across all categories
npm run benchmark

# Run validation baseline (uncalibrated)
npm run test:accuracy

# Run calibration training and validation
npm run test:accuracy:validation

# Run final frozen test split evaluation
npm run test:accuracy:final
```
